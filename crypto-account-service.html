Key Features

  • Non-custodial card spend: wallet → treasury at authorization, no pre-funding
  • Card authorization API for an issuer processor, HTTP/JSON, JIT Funding model
  • Spend contract in Solidity: expiry, refund, daily limit, roles, pause
  • Reconciliation: every debit matched to exactly one authorization
  • On-chain indexing from final blocks, with a reorg guard
  • Read-only Binance connector: spot, funding and Earn balances
  • Canonical ledger for exchanges and chains; multi-tenant gRPC API
  • Card quotes from Currency Rate Service

Design Highlights

TopicDecision
Non-custodial card spend Token allowance on the cardholder’s wallet; the contract holds nothing
Synchronous card, asynchronous chain Approve only after the debit is preconfirmed or included; a late debit is refunded automatically
No double debit Request idempotency, nonce stored before send, single-use authId in the contract
Bounded platform power Exchange keys read-only, any other permission refused; the only key that moves tokens lives in a separate binary, within allowance and daily limit

All decisions: README · 13 ADRs.

Card Authorization Flow

    participant P as Issuer processor
    participant A as card-auth
    participant R as CRS

    participant S as server (indexer)

    P->>A: Authorize(auth_id, card_ref, amount)
    A->>A: Idempotency, card status, limit
    A->>R: Rate, if currency is not USD
    A->>N: Read balance and allowance
    alt a check fails
        A-->>P: DECLINED + reason
    else all checks pass
        A->>N: debit(wallet, amount, authId, validUntil)
        N-->>A: Preconfirmed or included
        A-->>P: APPROVED
    end
    Note over A,S: Asynchronous part
    N-->>A: Finality reached → debit confirmed
    S->>N: Read Debited event
    S->>S: Ledger entry, reconciliation

Source and edge cases EC-1 … EC-12: PRD — Card Spend §3.3.2. Synchronous part (steps 1–8) measured on Base Sepolia: decision p95 0.696 s.

Boundaries

Non-custodial: CAS never holds user funds or signs for the cardholder.

Read-only on exchanges: no trading, no withdrawals; keys with other permissions refused.

Chains: test networks only. Binance: checked once on the owner’s account with a read-only key, deleted after the check.
